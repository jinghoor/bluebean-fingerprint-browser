# Agent 稳定性与速度优化（2026-11-03）

本轮是基于失败用例的执行策略、实现和回归优化，没有训练或修改模型权重。
没有调用在线 DSH 模型，因此测试结果不能代表模型任务成功率或完整任务加速比。

## 修复与改进

- 修复指定 selector 且使用 dom/complete 时，目标不存在仍可能返回条件满足的问题。
- 每次 observe 使用独立元素编号；上一轮编号不能误指向本轮其他元素。过期编号及
  缺少观察结果都返回 STALE_OBSERVATION 和 action_sent:false，不触发输入。
- observe 在一次渲染进程调用和一轮 DOM 遍历中生成元素列表及内部基线摘要。
  摘要与原实现的计数、名称和指纹一致，不重复塞进 Agent 输出。无效观察不会被
  当作空页面成功返回，失败后也不再保留旧观察。
- 目标定位过程缓存本次调用内的同级节点分组和 id 数量；没有向网站安装全局对象、
  DOM 标记、观察器或持续轮询脚本。
- 仅检查 DOM/URL/加载状态时跳过页面全文和布局读取；一次等待复用探测表达式。
- 本机控制 HTTP 直连回环地址，不继承系统代理。网页自身的代理及环境隔离设置不变。
  显式指定的控制端口失联时不会自动寻找其他浏览器。权属检查失败不在同一步中重复
  发现目标；已确认的新目标直接复用，减少重复查询。
- DSH 提示明确使用最新完整元素 id、避免整页轮询和固定休眠、批量提交已确定的
  步骤，并保留提交后的业务确认与未知结果不重放原则。

## 本地对比

使用同一个私有桌面中的开发内核和本地 1000 控件页面；旧源码只读备份作为基线。
每轮每个版本 24 个样本，交替执行顺序，比较“识别页面并生成摘要”。

| 项目 | 优化前 | 优化后 |
| --- | --- | --- |
| 每次识别及摘要的渲染进程调用 | 2 | 1 |
| 第一轮中位耗时 | 4.451 ms | 3.428 ms |
| 第二轮中位耗时 | 4.922 ms | 3.426 ms |
| 第二轮 P95 耗时 | 5.586 ms | 4.453 ms |
| 无文本条件的 DOM 等待读取页面全文 | 1 次 | 0 次 |
| selector 不存在、但文档已就绪 | 可能误报成功 | 正确等待并超时 |

两轮中该环节中位耗时下降约 23%–30%。这是本地确定性页面的局部测量，不能直接
推算真实网站、网络延迟、模型推理和用户整体任务的提速幅度。

## 验证

- 98 项 Python 回归通过：等待、故障处理、会话范围、启动兼容和打包依赖发现。
- 19 项 DSH 插件实 HTTP 检查通过；管理风险确认和会话范围规则保持。
- 两轮原生回归均通过，每轮包含 20 个场景记录和连续 20 次导航/观察/提交。
  每次只提交一次，额外尝试的 5 次旧编号操作都被拦截。
- 慢资源、延迟目标、遮挡、移动、局部出屏、输入、只读输入、过期文档、重定向、
  SPA 业务结果及错误系统代理均经过隔离浏览器验证。
- 前后摘要逐字段一致。全部原生输入来自测试专用浏览器，用户输入桌面保持不变。
